# Authentication Flow: Signup & OTP Verification

This document outlines the signup and OTP verification flow for the Azaniah backend authentication system.

## Overview

The authentication system uses a two-step verification process:
1. **AccountView (POST)** - Initial signup request with email validation
2. **VerifyOTPView (POST)** - OTP verification to complete account creation

## Signup Flow (AccountView)

### Endpoint
`POST /api/auth/signup/`

### Request Body
```json
{
  "Email": "user@example.com",
  "First_name": "John",
  "Last_name": "Doe",
  "Password": "securepassword123"
}
```

### Process
1. **Serializer Validation** - `AccountSerializer` validates input data
   - Email format validation (automatic from `EmailField`)
   - **Email Uniqueness Check** - Django's `unique=True` constraint on the Email field automatically validates that no account with this email exists
2. **Duplicate Account Detection**
   - Checks if email exists in `Account` model
   - Also checks `User` model (Django's auth user model)
3. **OTP Generation** - Generates a random 6-digit OTP
4. **Cache Storage** - Stores user data and OTP in cache with 600-second (10-minute) timeout:
   ```python
   cache_data = {
       'user_data': serializer.validated_data,
       'otp': otp
   }
   cache.set(f'signup_user_{email}', cache_data, timeout=600)
   ```
5. **Async Email Sending** - Sends OTP email in background thread (non-blocking)

### Responses

**Success (200)**
```json
{
  "message": "OTP sent successfully, check your email!",
  "Email": "email"
}
```

**Account Already Exists (400)**
```json
{
  "error": "Account already exists!",
  "message": "These details already exist in our system, please sign in!"
}
```

**Validation Error - Duplicate Email (400)**
```json
{
  "Email": ["account with this Email already exists."]
}
```
> ⚠️ **Note:** This error is automatically generated by Django's ORM due to the `unique=True` constraint on the Email field in the Account model. It occurs during serializer validation when a duplicate email is detected.

## OTP Verification Flow (VerifyOTPView)

### Endpoint
`POST /api/auth/verify-otp/`

### Request Body
```json
{
  "Email": "user@example.com",
  "OTP": "123456"
}
```

### Process
1. **Retrieve Cached Session** - Looks up cached signup data using email
2. **OTP Validation** - Compares provided OTP with cached OTP
3. **Duplicate Check** - Verifies account hasn't been created in the interim
4. **Account Creation** - Creates Account and Profile in database
5. **Clear Cache** - Removes signup session from cache

### Responses

**Success (201)**
```json
{
  "message": "Account created successfully!",
  "account": {
    "Email": "user@example.com",
    "First_name": "John",
    "Last_name": "Doe"
  },
  "profile": {
    "Email": "user@example.com",
    "Username": "",
    "Phone": "",
    "Country": "",
    "Address": "",
    "Favourite_genres": []
  }
}
```

**Invalid/Expired Session (400)**
```json
{
  "error": "Signup session expired or invalid email"
}
```

**Invalid OTP (400)**
```json
{
  "error": "Invalid OTP"
}
```

**Email Already Registered (400)**
```json
{
  "error": "Email already registered",
  "message": "An account with this email already exists. Please sign up instead."
}
```

## Key Implementation Details

### Email Uniqueness Constraint
The `Account` model defines Email with:
```python
Email = models.EmailField(unique=True)
```

This creates a database-level constraint that:
- Prevents duplicate emails at the database level
- Automatically generates validation error messages during serializer validation
- Is enforced before any view logic executes
- Returns the error message: `"account with this Email already exists."`

### Duplicate Checking Strategy
Multiple layers ensure no duplicate accounts are created:
1. **Model Level** - `unique=True` on Email field
2. **Serializer Level** - DRF validates database constraints during `is_valid()`
3. **View Level** - Explicit check before creating account:
   ```python
   if Account.objects.filter(Email=email).exists() or User.objects.filter(email=email).exists():
   ```

### Caching & Session Management
- OTP sessions stored in Django cache (configurable backend)
- 10-minute timeout ensures security and prevents retry attacks
- Cache automatically cleared after successful signup or expired via timeout

### Async Email Sending
- Email sending runs in background thread to avoid blocking request
- Uses `threading.Thread` with daemon flag
- Includes logging for debugging and monitoring
- Doesn't block API response

## Password Handling

The Account model's `save()` method automatically:
- Detects if password is already hashed (starts with `pbkdf2_sha256$`)
- Hashes plain-text passwords using Django's default hasher
- Prevents double-hashing on subsequent saves

```python
def save(self, *args, **kwargs):
    if self.Password and not self.Password.startswith('pbkdf2_sha256$'):
        self.Password = make_password(self.Password)
    super().save(*args, **kwargs)
```

## Error Handling Summary

| Error | Status | Source | Message |
|-------|--------|--------|---------|
| Duplicate Email (after validation) | 400 | Serializer | `"account with this Email already exists."` |
| Duplicate Email (after OTP) | 400 | View | Custom message |
| Missing Email/OTP fields | 400 | View | `"Email and OTP required"` |
| Session Expired | 400 | View | `"Signup session expired or invalid email"` |
| Invalid OTP | 400 | View | `"Invalid OTP"` |
| Serializer Validation Failure | 400 | Serializer | Field-specific errors |
